00 / In plain words

WHAT IT
DOES.

NOBAD Files is a desktop file manager for the servers you work on. Your own files on one side, the server's on the other.

1

Connect

Open a server over SSH/SFTP or FTP/FTPS. SSH host keys are checked: an unknown host asks you first, and a changed key is refused by default.

2

Browse and move

A dual local/remote pane shows both sides at once. Transfers go into a queue with progress, retry and cancel.

3

Sync, edit, deploy

Sync folders both ways, edit remote files with conflict detection, open a terminal, or run a deployment with backups, health checks and rollback.

01 / Features

YOUR
SERVERS.

What NOBAD Files is being built to do. It's still in development, so treat this as the plan for its first release, not a finished product.

01 / BROWSE

Dual pane

Local and remote files side by side, over SSH/SFTP or FTP/FTPS.

SFTP · FTPS
02 / TRANSFER

Transfer queue

Uploads and downloads wait in a queue with progress, retry and cancel. Files are written as .part until they're complete, so a cut-off transfer never looks finished.

.part safety
03 / RELAY

Server to server

Copy files from one server to another with the transfer manager's cross-server relay.

Cross-server
04 / SYNC

Two-way sync

Baseline-aware sync knows what changed on each side since last time. When both sides changed a file, you decide what happens to it, file by file.

Per-file decisions
05 / EDIT

Remote editing

Edit a file on the server. If it changed there while you worked, NOBAD Files notices and shows both versions side by side as a diff.

Conflict detection
06 / TERMINAL

Built-in terminals

Embedded SSH and local terminals, next to the files they work on.

SSH · Local
07 / VAULT

Credential vault

Saved logins are encrypted with your master password (Argon2id + AES-GCM). Saved secrets live in your operating system's keyring.

Master password
08 / TRUST

Host keys verified

An unknown SSH host is shown to you before you connect. A host whose key has changed is refused by default.

On by default
09 / DEPLOY

Deployments

Deployments to your servers come with backups, health checks and rollback.

Backups · Rollback
02 / Security

KEYS
STAY LOCKED.

A file manager holds the keys to your servers. These are the protections it's being built around.

Host keys

Verified, not assumed

Unknown SSH host: you're asked before connecting. Changed key: refused by default.

Vault

Master password

The credential vault is encrypted with a master password, using Argon2id and AES-GCM.

Keyring

OS keyring

Saved secrets are kept in your operating system's keyring.
